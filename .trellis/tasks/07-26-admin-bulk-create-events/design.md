# 技术设计

## 边界

本功能新增一条经过管理员认证的批量导入工作流，不改变公开投稿合同：

1. `/admin/events/bulk` 渲染导入界面，并挂载负责选择文件、预览、确认重复警告、提交和展示成功结果的 Svelte 组件。
2. `GET /api/admin/events/bulk/template` 返回带 UTF-8 BOM 的 CSV 模板。
3. `POST /api/admin/events/bulk/preview` 解析并校验上传文件，再读取一次 D1 查找疑似重复活动；该接口绝不修改 D1。
4. `POST /api/admin/events/bulk` 在调用批量持久化操作前，重新执行解析、校验和重复检测。
5. D1 查询层在单个 `db.batch()` 事务中写入已发布活动、规范标签、标签关系和每条活动的审计记录。

三个 API 路由都位于现有 `/api/admin/**` 中间件边界内，并沿用现有 JSON 封装。

## 数据流

```text
CSV 文件
  -> 预览 API
  -> 严格 CSV 解码 + 共享活动校验
  -> 重复项查询
  -> 记录 / 错误 / 警告
  -> 管理员确认警告
  -> 提交 API 重新执行相同的解码、校验和查询
  -> D1 原子批次
  -> 已创建活动摘要
  -> 带编辑链接的成功列表
```

浏览器发送的规范化活动对象不是权威数据。浏览器保留原始 `File`，确认时再次上传；服务端在两次请求中都负责解码和校验。

## CSV 合同

模板使用 UTF-8 BOM，并按以下顺序包含固定中文表头：

| CSV 列名 | 内部字段 | 规则 |
| --- | --- | --- |
| 活动名称 | `title` | 必填 |
| 活动类型 | `type` | 必填；接受现有代码或中文标签 |
| 活动规模 | `scale` | 必填；接受现有代码或中文标签 |
| 行政区代码 | `division_code` | 必填区县级代码 |
| 场馆 | `venue` | 必填 |
| 详细地址 | `address` | 可选 |
| 开始日期 | `start_date` | 必填，格式为 `YYYY-MM-DD` |
| 结束日期 | `end_date` | 必填，格式为 `YYYY-MM-DD` |
| 开始时间 | `start_time` | 可选，格式为 `HH:mm` |
| 结束时间 | `end_time` | 可选，格式为 `HH:mm` |
| 封面URL | `cover_url` | 可选 HTTP(S) URL |
| 活动描述 | `description` | 可选；支持带引号的多行 CSV 字段 |
| QQ群 | `qq_group` | 可选 |
| 购票地址 | `ticket_url` | 可选 HTTP(S) URL |
| 来源链接 | `source_url` | 必填 HTTP(S) URL |
| 联系信息 | `submitter_contact` | 必填，与单条创建合同一致 |
| 标签 | `tags` | 必填；以 `、` 分隔，包含 1 至 12 个不重复标签 |

页面在下载控件附近列出现有活动类型、规模的中文标签和代码。下载模板只包含 BOM 与表头，原样上传空模板不会创建示例数据。

使用成熟的 `csv-parse` 包及其浏览器安全的同步 ESM 导出。服务端从字节执行严格 UTF-8 解码，支持 BOM，严格检查列数，跳过空行，并限制单条记录大小。API 在解析前拒绝超过 1 MiB 的文件，并拒绝缺失、多余、乱序或重复表头。

## 共享校验

`src/lib/admin/form.ts` 继续作为管理员活动校验的唯一所有者。将字段规则提取到基于原始记录读取器的共享逻辑，并保留 `parseEventForm(FormData)` 作为单条创建和编辑路由的兼容适配器。新增携带内部字段键的结构化校验错误，同时保持现有面向用户的错误消息。

CSV 适配器把中文表头映射到现有内部字段，通过 `EVENT_TYPES` 和 `EVENT_SCALES` 把中文标签或代码规范化，并调用同一共享校验器。CSV 错误补充逻辑记录序号和中文字段名。解析器在一个响应中返回所有记录错误，而不是遇到第一条无效活动就停止。

## 预览与重复项合同

预览响应使用以下结构：

```ts
interface BulkPreviewData {
    valid: boolean;
    rows: Array<{ row: number; event: AdminEventInput }>;
    errors: Array<{ row: number | null; field: string | null; message: string }>;
    warnings: Array<{
        key: string;
        row: number;
        source: "csv" | "database";
        matches: Array<{ id?: number; row?: number; title: string }>;
    }>;
}
```

重复键由去除首尾空白、折叠连续空白并统一大小写后的 `title`、`start_date` 和 `venue` 组成。CSV 内部重复项在内存中比较；数据库检测以所有待导入开始日期执行一次有界候选查询，再在 TypeScript 中应用相同规范化规则。

提交请求携带原始文件和管理员已确认的精确警告键。CSV 警告键标识重复键及两条记录序号；数据库警告键标识重复键及匹配活动 ID。服务端重新计算警告，因此新出现的匹配会生成新键。任何未确认警告都返回 HTTP 409 和更新后的预览详情。校验失败返回带结构化详情的 HTTP 400；未认证请求沿用 HTTP 401 封装。

## D1 原子写入

新增批量专用查询函数，不循环调用 `createPublishedEvent()`。该函数分配连续候选 ID 区间，构造全部预编译语句，然后只调用一次 `db.batch()`：

1. 一条使用 `json_each(?)` 的语句通过 `INSERT OR IGNORE` 写入所有不重复标签。
2. 每条记录使用一条活动插入语句，以显式候选 ID 写入 `published` 和 `published_at`。
3. 每条记录使用一条关系语句，从 JSON 标签数组解析规范标签或别名并写入 `event_tags`。
4. 一条使用 `json_each(?)` 的语句写入全部活动的 `create` 审计记录，元数据包含 `source = "admin-bulk-create"`、CSV 记录序号、批次数量、标签和管理员身份。

单批达到 20 条记录时，确认请求使用以下 D1 查询预算：

| 操作 | 查询数 |
| --- | ---: |
| 重复候选查询 | 1 |
| 候选 ID 区间查询 | 1 |
| 不重复标签写入 | 1 |
| 活动写入 | 20 |
| 标签关系写入 | 20 |
| 审计记录写入 | 1 |
| 合计 | 44 |

该预算低于 D1 免费计划每次 Worker 调用 50 条查询的限制；其中 `db.batch()` 包含 42 条语句并构成一个事务。若并发创建占用了候选 ID，整个序列回滚，API 返回 HTTP 409 并要求管理员重新预览；同一次调用内不自动重试，避免超出免费计划查询预算。

## 界面状态与无障碍

新增 `BulkEventImport.svelte` 操作界面，并使用稳定状态：初始、预览中、无效、可提交、等待警告确认、提交中、成功和请求失败。文件输入、下载按钮、重置操作、警告复选框和确认按钮复用现有 UI 原语与 Lucide 图标。预览使用一张可水平滚动的语义化表格，不嵌套卡片。错误和警告使用 `role="alert"` 或状态区域；每次服务端响应后，焦点移动到结果标题。

导航增加独立的 `bulk` 类型和“批量导入”项目，桌面端与移动端保持一致。该路由不能错误激活“增加活动”或“已发布活动”。

## 兼容性、安全与回滚

- 现有单条创建 API 和 `AdminEventForm` 字段名保持稳定。
- 公开投稿路由、Turnstile 行为和 `pending` 状态保持不变。
- 即使上传者是管理员，也把 CSV 字节视为不可信输入并限制大小。服务端不信任 MIME 类型，独立校验扩展名、大小、UTF-8 编码、表头合同、记录数量和每个字段。
- 不持久化上传文件或预览负载；审计记录只保留追踪已创建活动所需的规范化元数据。
- 回滚时一起移除批量页面、三个 API 路由、解析模块、批量查询函数、导航项目、测试和新增依赖；不需要数据库迁移。

## 延后事项

- XLSX/JSON 输入、部分成功、模糊重复匹配、导入历史、结果导出和超过 20 条记录的异步批次。
- 通用导入框架；本次实现只负责管理员活动 CSV 导入。
