# 活动分类导航单页

## Goal

新增一个公开的“分类浏览”单页，集中展示当前确实关联活动的标签、活动类型和活动规模，帮助用户从分类入口直接进入已经应用对应条件的活动列表。

## Background

- 现有活动列表路由为 `/events`，已支持 `tag`、`type`、`scale` 查询参数。
- 活动列表默认只展示已发布且未结束的活动，也可通过 `status=ended` 或 `status=all` 改变时间范围。
- 活动类型和规模的名称与中文标签由 `src/lib/events/options.ts` 统一维护。
- 标签使用规范标签；别名标签不应作为独立入口展示。
- 现有 `topTags()` 只返回最多 20 个未结束活动标签，不能满足“展示所有”的要求。

## Requirements

- 新增公开路由 `/categories`，页面标题为“分类浏览”。
- 页面分为“标签”“活动类型”“活动规模”三个清晰区段。
- 统计范围为全部 `published` 活动，包含已结束活动；`pending`、`rejected`、`offline` 不参与统计。
- 每个区段只展示至少关联 1 个统计范围内活动的项目，不展示空分类。
- 标签展示全部规范标签，不受现有活动列表热门标签 20 条上限影响。
- 类型和规模使用 `src/lib/events/options.ts` 中的中文标签，链接值使用对应的稳定 `name`。
- 每个项目展示名称和活动数量；标签按活动数量降序、名称升序排列，类型和规模保持配置顺序。
- 点击项目跳转到 `/events` 并携带单个对应筛选参数：
  - 标签：`/events?status=all&tag=<encoded-name>`
  - 类型：`/events?status=all&type=<name>`
  - 规模：`/events?status=all&scale=<name>`
- 跳转链接的 `status=all` 与分类计数口径保持一致，确保目标列表包含该分类所统计的活动。
- 页面使用现有 `Layout.astro`、设计令牌、响应式布局和可见焦点样式。
- 桌面和移动主导航增加“分类”入口，并正确标记当前页。
- `/categories` 加入 sitemap。
- 数据加载失败时显示明确错误状态，不渲染误导性的空分类。

## Acceptance Criteria

- [x] 访问 `/categories` 可看到标签、活动类型和活动规模三个区段。
- [x] 三个区段均只包含至少有 1 个 `published` 活动的项目，并显示准确活动数量；已结束活动计入，其他状态不计入。
- [x] 所有规范标签均可展示，数量超过 20 时不会被截断；标签别名不会独立出现。
- [x] 类型和规模使用既有中文标签及既有配置顺序。
- [x] 点击任一分类项后进入 `/events`，URL 包含 `status=all` 和对应筛选参数，列表应用同口径筛选。
- [x] 主导航可从桌面和移动端进入该页面，并在 `/categories` 上显示当前状态。
- [x] sitemap 包含 `/categories`。
- [x] 数据库查询和页面契约有回归测试，类型检查、lint、测试和 Astro 构建通过。

## Out of Scope

- 不新增组合筛选、搜索框或分类详情页。
- 不修改活动列表现有筛选参数语义。
- 不修改后台的类型、规模或标签管理能力。
- 不展示没有任何符合统计范围活动的预置类型或规模。
