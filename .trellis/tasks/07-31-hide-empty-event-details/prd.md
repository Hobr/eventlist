# 活动详情页隐藏未填写信息

## 目标

公开活动详情页只呈现实际填写的信息，避免用“未填写”或“暂无活动介绍”等占位内容干扰访客浏览。

## 已确认事实

- 公开活动详情页位于 `src/pages/events/[id].astro`。
- `address`、`description`、`qq_group`、`ticket_url` 是投稿表单中的可选字段。
- 当前页面在 `description` 为空时显示“暂无活动介绍。”，在 `address` 或 `qq_group` 为 `null` 时显示“未填写”。
- 当前页面已经在 `ticket_url` 为空时隐藏购票入口。
- 日期、地区和场地属于页面的基础公开信息，不在本次“未填写信息”范围内。
- `source_url` 目前是必填审核来源；当活动没有购票链接时，可作为访客获取活动信息的备用入口展示。
- 本次是局部展示逻辑调整，不需要修改数据表、公开查询、投稿表单或后台管理页面。

## 需求

- R1：公开活动详情页不得为未填写的可选字段显示占位文案、字段标签或空内容容器。
- R2：已填写的可选信息维持现有内容、链接行为和视觉层级。
- R3：隐藏可选信息后，页面不得留下无意义的标题、分隔线或空白栏位。
- R4：日期、地区、场地、下线提示和浏览量上报行为保持不变。
- R5：`null`、空字符串和仅含空白字符的值都按未填写处理。
- R6：有 `ticket_url` 时只展示购票入口；没有 `ticket_url` 但有 `source_url` 时展示活动来源入口；两者都没有时不渲染操作入口。`source_url` 不进入公开 JSON-LD。

## 验收标准

- [x] 可选字段未填写时，详情页中不存在对应标签、占位文案或空容器。
- [x] 可选字段有有效内容时，详情页仍显示对应内容或操作入口。
- [x] 所有可选字段均为空时，详情页布局仍连续、无空白内容列或孤立分隔线。
- [x] 有购票链接时不显示活动来源链接。
- [x] 没有购票链接但有活动来源时显示活动来源链接。
- [x] JSON-LD 中不包含来源/组织者链接。
- [x] 必填公开信息和既有活动状态行为不受影响。
- [x] 自动化检查覆盖空值与已填写值两种渲染分支，项目现有相关检查通过。

## 不在范围内

- 修改投稿或后台表单的必填/可选规则。
- 修改数据库结构、既有活动数据或公开查询字段。
- 删除或修改 `source_url` 在数据库、投稿、后台审核中的保存和校验。
- 重设计整个活动详情页。
- 修改活动列表页、首页或后台活动页面。
