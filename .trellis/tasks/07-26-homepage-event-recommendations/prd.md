# 首页活动推荐设计

## 目标

当大量 ACG 活动在同一时期举办时，帮助访客快速判断附近有哪些活动、哪些活动值得进一步查看。首页需要降低选择负担，同时提供本地和更广范围的发现入口，并把用户引导到完整活动目录，而不是让首页本身变成第二个完整目录。

## 背景

- 产品是一个轻量、半可信的公共活动目录，不包含用户账号、社交关系或社区功能。
- 当前首页从 URL、Cloudflare 请求信息或默认配置中解析地区，然后按开始日期加载该地区 8 场尚未结束的活动。
- 当前大图推荐只是选择第一场带封面的活动；现有系统没有热度表、独立访客去重或趋势查询。
- 活动日期必填，但开始和结束时间可以分别留空。现实中很多活动没有可靠时间，也有许多活动的开始日期或时间相同。
- 完整活动目录已经负责详细筛选和分页。首页各区域必须通过可复现的筛选条件链接到完整目录。

## 需求

### 发现结构

- R1. 首屏需要让访客识别当前地区、看到近期活动，并找到查看更多匹配活动的入口。
- R2. 即使匹配活动超过 100 场，首页也只排序和分组展示数量受控的活动子集。
- R3. 推荐行为必须确定且可解释，不引入不透明的个性化算法。
- R4. 地区选择保持突出，本地区域始终保留当前所选地区。
- R5. 重复活动项使用紧凑、便于扫读的行式布局；最多只有一场紧凑主推荐可以使用较大的图片。
- R6. 日期、地区、标题、场地、类型和规模在各视口下都必须清晰可读，不能产生水平溢出。
- R7. 每个推荐分组都必须链接到能够复现对应地区和日期条件的活动目录 URL。
- R8. 无数据、数据稀少、热度冷启动和查询失败状态必须明确且可继续操作。
- R9. 本功能不建立用户画像或跨活动行为历史。IP 派生数据只用于单场活动的访问去重，且永不对外暴露。
- R10. `附近活动` 与 `热门活动` 同时呈现在首页，不使用顶层模式切换。
- R13. 切换热度时间窗口时保持布局尺寸稳定，并保留当前所选地区。
- R14. 附近内容在前，热门内容紧随其后；首屏需要提供两个区域都清晰可见的页内跳转入口。

### 附近推荐

- R11. 附近活动使用当前所选地区，并按自然日期分组，而不是展示一条没有层次的长列表。
- R15. 附近推荐最多以一场紧凑主推荐开始，并展示简单明确的推荐理由。
- R16. 主推荐从当前地区未来 14 天内开始的活动中选出。活动规模优先，其次是开始日期的临近程度，封面只作为更后面的同分条件；没有封面的活动仍可入选。
- R17. 分组和排序不得推测缺失的时间。已知时间只作为可选展示信息。
- R18. 日期范围包含今天的跨日活动，在尚未结束时继续作为“正在进行”显示，即使具体时间未知。
- R19. 同日活动排序必须稳定。当首页数量上限隐藏了部分活动时，界面需要显示总数，并链接到精确日期筛选后的完整目录。
- R20. 附近推荐显示一个紧凑的“正在进行”分组，以及接下来 3 个存在活动的开始日期。每个日期分组最多显示 4 场非主推荐活动。
- R21. 日期分组内以规模作为有意义的排序条件；其余同分使用稳定的中性键，不使用时间或封面排序。

### 热度排行

- R12. 热度统计尚未结束活动在可切换的近 3 日、7 日和 30 日窗口内，由独立 IP 打开的活动详情次数。
- R22. 热门区域同时包含当前地区排行和全国排行，并共用同一个时间窗口。
- R23. 同一访客在一个统计窗口内，对同一活动最多贡献一次计数。原始 IP 不得由应用代码存储、记录日志或返回。
- R24. 本地排行和全国排行各最多展示 5 场；宽屏双列显示，窄屏上下排列。
- R25. 默认热度窗口为近 7 日；切换到 3 日或 30 日时，两份榜单同步更新。

## 验收标准

- [ ] A1. 在约 1440x1000 的视口中，首屏可见当前地区、紧凑主推荐、其他附近活动选择，以及清晰的 `附近活动` / `热门活动` 跳转入口。[R1, R5, R14]
- [ ] A2. 当匹配活动超过 100 场时，首页最多展示 1 场主推荐、4 场正在进行活动、3 个各含 4 场活动的日期分组，以及两个各含 5 场活动的热门榜。[R2, R20, R24]
- [ ] A3. 在日期、地区和数据集相同的情况下，主推荐选择结果稳定；无封面活动仍可入选，显示的推荐理由与规则一致。[R3, R15, R16]
- [ ] A4. 缺失时间不会产生虚构值或暗示不存在的先后顺序；同日活动使用规模和稳定中性键处理同分。[R17, R21]
- [ ] A5. 在跨日活动开始后、结束前，该活动持续显示在“正在进行”分组。[R18]
- [ ] A6. 日期分组和正在进行分组的链接会打开同一地区、精确日期条件下的目录结果，并显示可移除的活动筛选标签。[R7, R19]
- [ ] A7. 首页同时渲染附近和热门区域；热门默认近 7 日，并提供 3/7/30 日控制。[R10, R12, R25]
- [ ] A8. 本地榜和全国榜使用相同时间窗口同步更新，并且各自最多展示 5 场活动。[R22, R24]
- [ ] A9. 同一 IP 重复打开同一活动时，在每个窗口内只计一次；不同 IP 分别计数。D1 数据行和 API 响应中都不存在原始 IP。[R9, R23]
- [ ] A10. 附近主推荐不会再次出现在附近的正在进行或日期分组中。同一活动可以同时进入本地和全国热门榜，因为两个标题明确表达了不同排行语境。[R3, R22]
- [ ] A11. 空地区、没有正在进行活动、日期稀少、没有热度数据、缺少统计配置和 D1 失败都有明确行为，且绝不影响活动详情页正常显示。[R8]
- [ ] A12. 在约 390x844、768x1024 和 1440x1000 的视口中，控件和文本保持可读、可聚焦，不产生水平溢出或不合理重叠。[R6, R13, R24]

## 范围外

- 在首页渲染完整活动目录。
- 用户账号、兴趣收藏、协同过滤或行为个性化。
- 评论、点赞、关注、通知等社区功能。
- 管理员手动置顶功能。
- 修改投稿或审核流程。
- 引入第二套分析数据库、KV 镜像或第三方推荐服务。

## 风险和延期项

- 一个 IP 不等于一个人：NAT 可能导致少计，VPN 或移动网络地址变化可能导致多计。该指标只是轻量热度信号，不是经过审计的受众数据。
- 独立 IP 去重无法阻止来自大量不同地址的协同流量；复杂反作弊评分延后处理。
- 更换访问哈希密钥会中断去重连续性；实现文档必须说明有意重置的流程。
- 仓库当前将 `0001_init.sql` 视为尚未部署的基线。在执行任何远程迁移前，必须重新确认这一前提。
