# PRD：基于 Tailwind 与 Flowbite 重构前端

## 目标

在不改变现有业务能力、数据流和 Cloudflare 部署契约的前提下，基于 Tailwind CSS v4 与 Flowbite Svelte 重构“同频点”全站前端。公开站点需要形成具有品牌辨识度、适合中文 ACG 活动发现的高端浏览体验；管理后台需要在同一设计令牌和组件体系下保持紧凑、清晰、高效的工具属性。

## 背景与已确认事实

- 用户明确选择“公开站点高端品牌化、管理后台克制工具化”的双模式全站重构。
- 仓库已经在提交 `6c5375d` 完成 Flowbite 组件迁移；当前工作重点是视觉系统、信息层级、页面构图、交互反馈和状态呈现，而不是重复安装或机械替换组件。
- 当前技术栈为 Astro 7、Svelte 5、Tailwind CSS 4.3、Flowbite 4、Flowbite Svelte 1.33 和 Flowbite Svelte Icons 3.1；共享交互通过 `src/components/ui/` 的稳定适配层暴露。
- 公开页面包含首页、活动目录、活动详情和投稿页；管理页面包含登录、审核队列、发布队列、下线队列、创建、编辑、批量导入和标签管理。
- 当前 `corepack pnpm test` 的 14 项测试、`corepack pnpm build` 和 `corepack pnpm exec tsc --noEmit` 均通过。
- “同频点”品牌名称与口号已由提交 `7ec1b89` 集中到 `src/lib/site.ts`；本任务复用它们，不重新创作品牌文案。

## 范围

### 共享视觉基础

- 重构字体、色彩、间距、形状、阴影、焦点和动效令牌，移除 `Inter` 首选字体及相互竞争的装饰色。
- 保留系统偏好驱动的亮色与暗色模式，不新增手动主题开关。
- 保留 Flowbite Svelte、Flowbite Svelte Icons、本地 `ui/` 适配层和 `cn()` 类合并边界，不引入第二套运行时 UI 库。
- 统一 hover、active、focus、disabled、loading、empty、success 和 error 状态。

### 公开站点

- 重构全站导航、页脚和内容容器，建立清晰的品牌入口与当前页面状态。
- 首页采用真实活动图片驱动的非对称首屏，并在首屏内保留地区选择、主推荐和进入完整目录的直接路径；附近与热门活动仍在同一页面中连续呈现。
- 活动目录继续以可扫描的封面行和常用筛选为主，高级筛选继续使用可访问侧栏。
- 活动详情突出真实活动媒体、日期、地区、场地和操作信息，离线与不存在状态保持明确。
- 投稿页保持单个原生表单、必填字段常显、可选字段渐进披露和现有成功跳转。
- 新增与全站视觉一致的 404 页面；不虚构隐私政策或服务条款内容。

### 管理后台

- 保留桌面固定侧栏、移动顶部栏和单表格响应式任务卡结构。
- 统一管理导航、表格、表单、批量导入、确认弹层、分页及状态反馈的字体、颜色和交互节奏。
- 后台不采用公开站点的大字号英雄区、大留白或装饰性卡片堆叠；信息密度、列对齐和重复操作效率优先。

## 需求

### R1：设计系统

- 公开站点采用 Soft Structuralism 基调与非对称内容构图：冷中性背景、石墨文字、单一品牌强调色和真实活动图片提供的内容色彩。
- 管理后台使用相同字体、语义颜色、焦点和动效令牌，但采用更紧凑的间距与稳定表格结构。
- 禁止默认 `Inter`、紫蓝 AI 渐变、装饰性光球、通用灰边框堆叠、深黑硬阴影和无目的等分三卡布局。
- 重复卡片保持不超过 8px 的项目圆角规范；物理层次通过克制的双层边缘、色面和内高光表达，不创建卡片套卡片。

### R2：Flowbite 与组件边界

- 优先复用 Flowbite Svelte 及现有 Button、Badge、Table、Drawer、Modal、Select 适配器。
- 共享状态化 Flowbite 组件继续由 `src/components/ui/` 统一管理焦点、关闭、变体和项目令牌覆盖。
- 图标只使用 `flowbite-svelte-icons` 的细线图标；加载状态使用 Flowbite `Spinner`。
- 业务页面不得引入 Flowbite DOM 运行时、`initFlowbite()` 或 data-attribute 初始化。

### R3：功能兼容

- 保持全部路由、GET 查询参数、表单字段名、API 端点、重定向、Turnstile、Cloudflare Access、JSON-LD 和数据库行为不变。
- 保持目录筛选参数 `city`、`type`、`scale`、`tag`、`from`、`to`、`starts`、`active`、`page`、`sort` 的语义和单条件移除行为。
- 保持管理员创建、编辑、审核、驳回、下线、重新发布、批量导入和标签合并的现有状态流与确认规则。

### R4：交互与动效

- 所有可交互控件具备可见 focus、hover、active、disabled 和 pending 反馈；按压状态使用细微缩放，过渡使用项目自定义 cubic-bezier。
- 公开页面可使用基于 `IntersectionObserver` 的渐进式进入动画；无 JavaScript时内容必须保持可见，且 `prefers-reduced-motion` 必须禁用非必要动画。
- 动效只以 `transform` 和 `opacity` 为主，不使用持续 `scroll` 监听，不通过动画修改 `top`、`left`、`width` 或 `height`。
- `backdrop-blur` 只允许用于固定或粘性导航、抽屉和模态层。

### R5：响应式与无障碍

- 在 768px 以下，公开站点的非对称布局必须折叠为单列或明确的横向滚动区域；后台表格继续使用单一语义 `<table>` 的移动任务卡样式。
- 不使用 `h-screen`/`100vh` 构建公开首屏；首屏必须在常见移动和桌面视口中露出下一段内容线索。
- 中文文本不得遮挡、截断关键语义或溢出控件；触控目标、键盘顺序、表单 label、弹层 Escape 和关闭后焦点恢复必须可用。
- 正文文字与背景在亮暗模式下达到 WCAG AA 4.5:1；装饰图标隐藏于辅助技术，图标按钮具备可访问名称。

### R6：内容与媒体

- 首页和详情页优先显示真实 `cover_url`；缺图时继续使用项目内位图 `public/images/event-fallback.webp`，不得以渐变或抽象 SVG 代替主媒体。
- 保持中性、工具式、可扫描的中文文案，不加入营销口号、军事化术语或解释界面设计的可见文本。
- 数字、日期和时间使用等宽或 tabular figures，保证列表列宽稳定。

## 验收标准

- [ ] AC1：公开和管理页面均使用新的共享字体、语义颜色、焦点与动效令牌，生产源码不再把 `Inter` 作为首选字体。
- [ ] AC2：首页、目录、详情、投稿和 404 页面呈现统一的高端品牌视觉；首页首屏包含真实活动媒体、地区选择、主推荐和目录入口，并露出后续内容。
- [ ] AC3：登录及所有管理页面呈现统一的紧凑工具界面，桌面列对齐与移动单表格任务卡行为保持可用。
- [ ] AC4：Flowbite 适配层、图标和组件状态工作正常，生产源码不存在 `bits-ui`、Lucide、`initFlowbite()` 或第二套主题状态。
- [ ] AC5：现有路由、查询参数、表单字段、API 请求、重定向、管理员动作、弹层确认及关闭后焦点恢复均未回归。
- [ ] AC6：约 390x844、768x1024、1440x1000 下无页面级水平溢出、文字遮挡、控件重叠或不可触达操作；稳定媒体不会因加载或 hover 改变布局尺寸。
- [ ] AC7：亮暗模式、键盘焦点、Escape、减少动效、错误、空数据、加载和禁用状态均通过人工或自动化检查。
- [ ] AC8：`corepack pnpm test`、`corepack pnpm build`、`corepack pnpm exec tsc --noEmit`、Prettier 与 `git diff --check` 通过；lint 结果只允许保留项目已记录的 TypeScript 7 上游加载阻断。
- [ ] AC9：视觉审计未发现本 PRD 禁止的模板模式，且代码 diff 不包含后端业务、API、数据库或无关依赖改动。

## 范围外

- 后端业务规则、API 响应结构、数据库 schema、迁移和 Cloudflare 绑定的主动重构。
- 新增活动业务能力、管理工作流或前端全局状态框架。
- 手动主题切换、Toast 系统、滚动惯性库、动画框架或第二套 UI/CSS 框架。
- 编写未经产品或法律确认的隐私政策、服务条款和 Cookie 文案。
- 为视觉验收新增 Playwright 项目依赖，或为 lint 上游兼容问题降级 TypeScript。
