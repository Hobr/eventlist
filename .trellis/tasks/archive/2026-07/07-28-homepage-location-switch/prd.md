# 首页地区无刷新切换

## Goal

让用户在首页导航栏的地区侧栏中选择省、市或区县后，无需刷新整个网页即可切换当前地区，并同步看到该地区的主推荐、热门活动和今日活动；同时保留可分享 URL、浏览器历史、地区偏好、直接 URL 服务端渲染和请求失败后的普通导航回退。

## Background

- `src/components/CitySelector.svelte:23` 当前在每次省、市、区县选择变化时调用 `navigateToDivision()`。
- `src/lib/division-preference.ts:19` 当前通过 `window.location.assign()` 或 `window.location.replace()` 完整导航，因此每一级选择都会刷新页面。
- 首页主推荐和热门榜已经是 hydrated Svelte 组件，但今日活动仍由 Astro 服务端标记渲染；地区切换需要统一更新三个内容区块及导航栏标签。
- 热门榜已支持无刷新 `3 / 7 / 30` 日切换、请求取消、页面内缓存和 URL 同步，可以复用其公开 DTO 与竞态处理原则。
- 用户已选择首页局部数据更新方案，不采用影响全站导航的 Astro `ClientRouter`。

## Requirements

1. 首页地区侧栏中的省、市、区县选择只更新侧栏内的待应用值，不得立即请求数据或导航。
2. 侧栏提供明确的“应用地区”操作；只有用户应用一个有效地区后才开始切换首页内容。
3. 地区切换不得产生文档级导航、白屏、页面滚动位置重置或全站客户端路由行为。
4. 请求成功后必须在一次一致的状态提交中更新：
   - 桌面端和移动端导航栏地区简称及完整说明；
   - 主推荐候选及零、单、多候选轮播状态；
   - 当前热度窗口下的本地和全国热门榜；
   - 今日所选地区活动及“浏览更多本地活动”链接。
5. 请求期间保留当前地区和全部现有内容，显示清晰但不遮挡浏览的加载状态；成功前不得提前修改 URL、导航标签或地区偏好。
6. 请求失败时保留当前地区和内容，显示可理解的行内错误，并允许用户重试或选择其他地区。
7. 快速连续应用地区时必须中止或忽略旧请求，迟到响应不得覆盖最新选择。
8. 成功后将 `city` 写入当前首页 URL，并保留现有 `trend`；使用浏览器历史记录，使返回/前进可以无刷新恢复相应地区和首页数据。
9. 成功后才将地区写入现有 `eventlist.divisionCode` 本地偏好；失败或取消不得污染偏好。
10. 热门榜缓存按“地区代码 + 热度窗口”隔离；返回之前访问过的组合时可以复用成功缓存，但不得跨地区复用榜单。
11. 首页按需接口必须严格验证地区与热度窗口，只返回主推荐、热门榜、今日列表和地区标签实际展示所需的公开字段，不得序列化完整数据库记录或投稿/审核字段。
12. 异步请求失败时提供指向 `/?city=<code>&trend=<window>` 的普通导航回退；现有地区侧栏本身依赖 JavaScript，本任务不新增无 JavaScript 级联省市县选择器。
13. 首页初次服务端渲染、直接访问或分享 `/?city=<code>&trend=<window>` 的行为保持不变；禁用 JavaScript 时直接 URL 仍可由服务端正确渲染。
14. 地区切换不得改变主推荐候选规则、热门榜统计规则、今日活动 10 条上限及现有活动详情/目录 URL 语义。

## Acceptance Criteria

- [ ] 改变省、市、区县选择时页面不导航；应用地区后地址栏和首页内容在无整页刷新的情况下同步更新。
- [ ] 应用前，导航标签、URL、地区偏好和首页内容仍代表当前已生效地区。
- [ ] 成功切换后，桌面与移动导航入口、主推荐、热门榜、今日标题/列表及本地目录链接全部使用同一新地区。
- [ ] 切换地区不会重置页面滚动位置；主推荐轮播和热门榜在新数据提交后进入有效的新状态。
- [ ] 加载期间旧内容保持可读，失败时旧地区仍然有效且错误可恢复。
- [ ] 快速连续应用两个地区时最终只显示最后一次选择，旧响应无法覆盖新结果。
- [ ] 热门榜在不同地区间不串用缓存；相同“地区 + 窗口”组合可以复用已成功加载的数据。
- [ ] 成功切换写入 URL 和本地偏好；返回/前进可无刷新恢复对应地区，刷新或分享 URL 得到相同服务端内容。
- [ ] 异步切换失败时可通过普通导航链接重新加载目标地区；直接访问目标 URL 在禁用 JavaScript 时仍可得到正确服务端内容。
- [ ] 首页公开响应及 hydrated 状态不包含联系方式、来源链接、审核状态或其他非展示字段。
- [ ] 自动化测试覆盖地区导航回退、公开 DTO/API 参数、竞态/缓存状态和主要内容同步；lint、TypeScript、测试及生产构建通过。

## Key Decisions

- 采用首页局部数据更新，不引入全站 Astro `ClientRouter`。
- 省、市、区县选择先保存在侧栏中，由“应用地区”一次提交，避免逐级请求。
- 内容切换成功后再更新 URL、历史记录和本地地区偏好。
- 首页各区块按同一响应原子切换，加载或失败时保留旧地区内容。

## Out Of Scope

- 将活动目录页、投稿页或管理后台的地区控件改为无刷新导航。
- 改变自动定位、默认地区或已保存地区的优先级；只把已保存地区恢复从整页导航改为局部更新。
- 修改活动推荐、热度计算、今日活动筛选和排序算法。
- 引入全站 SPA、Astro `ClientRouter` 或新的客户端路由框架。
- 新增无 JavaScript 的三级联动省市县选择器。
- 跨刷新持久化首页数据缓存或引入 Cloudflare Cache API。

## Risks And Deferred Items

- 今日活动目前是 Astro 标记，若要客户端更新必须增加公开 DTO 和可交互渲染边界；不得复制出与现有 `EventCard` 长期漂移的第二套全站卡片系统。
- 导航地区入口在桌面/移动布局下的标签与三个首页内容区块必须共享同一已生效地区，避免各 Svelte 岛之间出现数据不一致。
- 浏览器返回/前进需要处理 `popstate`；恢复失败时应保留当前内容并允许普通导航恢复，而不是留下 URL 与内容不一致。

## Notes

- 本任务跨越导航组件、浏览器状态、公开 API、数据库查询复用和三个首页展示区块，按复杂任务处理，需要 `design.md` 与 `implement.md`。
