# 首页主推荐轮播与热门榜无刷新切换

## Goal

让首页主推荐覆盖当前仍在进行的本地活动，并在存在多个优先候选时通过完整 Hero 卡片轮播提供更多有效选择；同时让热门活动的 `3 / 7 / 30` 日榜单在不刷新整页的情况下切换，保持首页浏览位置和上下文。

## Background

- 当前 `listHomepageDiscovery()` 在 `src/lib/db/queries.ts:439` 只返回一个 `featured` 活动，查询使用 `LIMIT 1`。
- 当前候选要求 `start_date` 位于中国本地日期的今天至未来 14 天之间，因此昨天或更早开始、但当前仍未结束的活动不会成为主推荐（`src/lib/db/queries.ts:452`）。
- 当前候选先按规模 `mega > large > mid > small`、再按开始日期、封面完整性和 ID 排序。
- 当前首页将唯一的 `discovery.featured` 直接渲染为整块 Hero（`src/pages/index.astro:123`）。
- 项目已经依赖 Flowbite Svelte，其 `Carousel` 支持滑动、受控索引和控制组件；首页交互应作为 Svelte 岛实现，不引入新的 UI 运行时。
- 当前热门活动切换链接导航到 `/?city=<division>&trend=<window>#popular`，因此每次选择都会重新请求和渲染整页（`src/pages/index.astro:104`）。
- 当前主推荐和热门列表都由 Astro 服务端标记渲染；`EventRecord`/`PopularEvent` 包含投稿人联系方式等非展示字段。改为 hydrated Svelte 组件时必须先投影为首页公开 DTO，不能把完整数据库记录序列化到浏览器。

## Requirements

### Main Recommendation

1. 主推荐只展示已发布且匹配当前所选地区的活动。
2. 已经开始但当前仍未结束的活动应具有主推荐资格，不限制其开始日期必须是今天或以后。
3. 尚未开始的活动继续只考虑中国本地日期今天起至未来 14 天内的候选。
4. “未结束”沿用公共活动目录规则：结束日期早于今天视为结束；结束日期为今天且存在已经到达的 `end_time` 时视为结束；无结束时间的活动在结束日期当天全天保持候选资格。
5. 当前正在进行的候选优先于尚未开始的候选；“正在进行”指开始日期早于今天，或开始日期为今天且未填写开始时间/开始时间已到。各组内继续按规模 `mega > large > mid > small`、开始日期、封面完整性和 ID 稳定排序，最多返回前 5 个候选。
6. 一个候选时显示单张主推荐卡片，不显示无意义的轮播控制。
7. 整个现有 Hero 作为主推荐卡片；多个候选时，背景封面和活动信息作为完整卡片一起轮播，站名与简介在各张卡片中保持相同位置和视觉层级，不在 Hero 内嵌套第二张卡片。
8. 每张候选卡片包含真实活动封面（缺失或加载失败时使用现有位图占位图）、标题、时间、推荐说明和详情入口；hydrated 组件只接收这些展示所需字段，不接收完整 `EventRecord`。
9. 多候选轮播每 6 秒自动切换；鼠标悬停、轮播内键盘焦点停留、用户主动暂停或系统启用 `prefers-reduced-motion` 时暂停。主动暂停状态优先于自动恢复。
10. 轮播使用 Flowbite Svelte 与 Tailwind v4，支持显式上一张/下一张、播放/暂停、分页指示、方向键、触摸滑动和明确的可访问名称。
11. 无候选、地区解析失败及数据查询失败时保留清晰的现有降级路径。

### Popularity Switching

12. 热门活动初次加载继续由 Astro 服务端渲染 URL 中的 `trend`（无效或缺失时为 7 日），保证首屏内容和无 JavaScript 降级链接可用。
13. 用户选择另一个热度窗口时，由 Svelte 组件按需请求该地区和窗口的本地/全国榜单；成功结果按窗口缓存，同一页面会话内再次选择不得重复请求。
14. 切换成功后使用 `history.replaceState` 更新地址栏中的 `city`、`trend` 和 `#popular`，不得触发页面导航；刷新或分享该 URL 时应恢复相同地区与热度窗口。
15. 按需请求期间保留当前已显示榜单，在被选择的窗口上显示 Flowbite 加载状态；快速连续选择必须取消或忽略过期请求，旧响应不得覆盖较新的选择。
16. 按需请求失败时保留当前榜单和窗口，显示可理解的行内错误，用户可重试或选择其他窗口。
17. 新增公开 GET 接口必须验证 `city` 和 `trend`，使用现有 JSON envelope，并只返回热门列表实际展示的 `id`、`title`、`division_code`、`start_date`、`unique_visitors`；不得返回联系方式、来源链接、审核字段或其他完整活动记录字段。
18. 热门切换控件保持三段式视觉与可访问 tab 语义，支持键盘操作、焦点样式和 `aria-busy`/错误播报。

## Acceptance Criteria

- [ ] 昨天或更早开始但当前仍未结束的已发布本地活动可以进入主推荐候选。
- [ ] 已结束、未发布、地区不匹配或开始日期晚于未来 14 天的活动不会进入候选。
- [ ] 当前正在进行的活动排在尚未开始的活动之前，同组候选维持规模优先的稳定顺序。
- [ ] 一个候选时渲染单张主推荐卡片且不出现上一张、下一张、播放/暂停或分页指示器。
- [ ] 多个候选时可通过轮播控制、键盘和触摸在卡片之间切换，每张卡片链接到正确的活动详情页。
- [ ] 多候选轮播默认每 6 秒切换，并在悬停、焦点进入、用户主动暂停或减少动态效果时暂停；一个候选时不启动定时器。
- [ ] 轮播不会导致桌面或移动端溢出、布局跳动或文字遮挡。
- [ ] 查询排序、5 个候选上限和候选数组返回值有聚焦自动化测试；零、单、多候选行为有本地浏览器验证记录。
- [ ] 切换热门榜窗口不会产生文档级导航或重置页面滚动位置，成功后列表、选中态和 URL 参数一致。
- [ ] 首次按需加载后结果被缓存；快速连续选择不会显示过期响应，加载失败不会清空当前榜单。
- [ ] 禁用 JavaScript 时，`3 / 7 / 30` 链接仍可通过原 URL 完整导航查看对应榜单。
- [ ] 热门榜 API 对无效地区/窗口返回 400 JSON，对查询失败返回稳定的 500 JSON，并且成功响应不包含任何非展示字段。
- [ ] 主推荐和热门榜的首页公开 DTO、窗口解析有聚焦自动化测试，证明 hydrated props/API JSON 均不含内部字段；API、无刷新切换、缓存和错误状态有本地路由/浏览器验证记录。
- [ ] lint、TypeScript、测试和生产构建全部通过。

## Key Decisions

- 最多展示 5 个主推荐候选。
- 当前正在进行的活动优先于尚未开始的未来活动。
- 整个现有 Hero 作为轮播卡片，不增加嵌套卡片。
- 多候选时每 6 秒自动播放，并提供临时暂停与用户主动暂停机制。
- 热门榜采用按需 JSON 请求并按窗口缓存，不在首页首次加载时预取三套排行。
- 热门榜成功切换使用 `history.replaceState`，避免刷新和历史栈污染，同时保留可分享 URL。
- 两个 hydrated 首页组件和公开接口只消费最小公开 DTO，不序列化完整 `EventRecord`/`PopularEvent`。

## Out Of Scope

- 修改今日活动的数据查询、排序、10 场上限或列表/空状态结构；标题与目录 CTA 可收紧为更简洁的地区化文案。
- 引入基于访问量的新主推荐评分算法。
- 修改活动目录页的筛选与排序规则。
- 新增后台人工置顶或推荐位管理功能。
- 把首页改造成全站 SPA，或引入 Astro ClientRouter/新的客户端路由运行时。
- 跨页面、跨刷新持久化热门榜客户端缓存。

## Risks And Deferred Items

- 当前主推荐仍以规模为主要质量信号；访问热度不进入主推荐评分，后续如需调整应单独定义推荐算法。
- 不持久化用户的轮播播放/暂停偏好；刷新页面后恢复默认行为，但系统级减少动态效果始终优先。
- 不为本任务引入新的浏览器测试框架；响应式、交互和图片降级通过现有构建检查与本地浏览器验证。
- 热门榜首次切换需要一次额外 D1 查询；组件保留当前内容并缓存成功结果，以更低的首页基础查询成本换取一次轻量等待。
- 新增 hydrated props 与公开 JSON 边界存在字段泄漏风险；共享首页投影函数和响应形状测试必须证明联系方式等内部字段未被序列化。
