# 扩展活动详情与入场信息

## Goal

让活动详情页同时承担“确认活动当前状态、主办主体”和“判断如何入场”的职责：完整展示已有的公开来源、更新时间、热度和状态，并允许投稿者或管理员补充主办方、异常状态、入场方式、票价与开售/预约/申请时间。

## Background

- 当前详情页在 `ticket_url` 存在时主动隐藏 `source_url`（`src/lib/events/detail.ts:13-30`）。新规则要求两个 URL 不同时均显示，相同时只保留购票入口。
- `updated_at` 已进入 `PublicEventDetail`，但详情页尚未渲染（`src/lib/db/public-events.ts:40-47`、`src/pages/events/[id].astro:77-262`）。
- 活动访问热度来自 `event_visitors` 的活动级匿名访客去重记录；首页已使用 3/7/30 日窗口，详情页尚未查询或展示（`.trellis/spec/backend/database-guidelines.md:303-334`）。
- `events` 当前没有主办方、活动异常状态、入场方式、票价区间或开售/预约/申请时间字段（`migrations/0001_init.sql:15-77`）。
- 活动字段需要贯穿公开投稿、管理员新增/编辑、CSV 批量导入、D1 写入/读取及详情页。所有新增字段均为可选，空值不应产生占位文案或空白区块。

## Requirements

### R1. 来源与购票链接

- `ticket_url` 与 `source_url` 指向不同 URL 时，详情页同时显示“购票/预约入口”和“活动来源”。
- 两者指向同一 URL 时，只显示购票入口。
- 现有 URL 校验会通过 `new URL(...).toString()` 规范化投稿和管理员输入（`src/lib/public/form.ts:57-71`、`src/lib/admin/form.ts:108-124`）；页面比较不得因首尾空白或标准 URL 序列化差异重复展示同一链接。

### R2. 已有详情信息

- 显示活动信息最后更新时间 `updated_at`。
- 显示单一的用户状态“未开始 / 进行中 / 已结束 / 已延期 / 已取消 / 已下线”：数据库状态为 `offline` 时优先显示“已下线”，活动异常状态“取消”优先于“延期”，无异常状态时按北京时间及活动起止日期/时间推导其余三种状态；不额外显示“已发布”。
- 显示“近 30 日热度”：统计该活动当前保留在 `event_visitors` 中的匿名去重访客数，不公开 `visitor_key` 或任何可关联访客的数据。
- “近 30 日热度”为 `0` 时仍显示 `0`；它是系统统计项，不适用投稿字段的空值隐藏规则。
- 状态、更新时间和热度必须使用清晰的中文标签，不暴露数据库内部枚举或原始时间格式。

### R3. 新增可选活动字段

- 主办方：可选字符串，用于显示活动主办主体；允许多个主办方以一段文本表达。
- 活动异常状态：可选固定单选“延期 / 取消”；未填写表示活动状态正常，不显示额外异常字段，而是继续使用日期推导状态。
- 活动入场方式：可选固定单选，选项为“购票”“预约”“直接入场”“邀请”“其他”；不支持多选或自由文本。
- 票价区间：可选字符串；允许表达“免费”“80-280 元”“现场票价待定”等非结构化内容。
- 开始购票/预约/申请时间：使用必填关系为“日期可选、时间依赖日期”的一组字段；填写日期后可继续填写精确到分钟的可选时间。面向中国活动按北京时间解释和显示。
- 上述字段应支持公开投稿、管理员新增、管理员编辑和 CSV 批量导入。
- 字段为空时不在详情页显示，也不显示空标签、占位符或空容器。
- 延期或取消的具体公告继续写入现有“活动描述”，不新增独立公告字段。

### R4. 重构边界与隐私

- 网站仍处于开发阶段，允许重构并重建开发数据库；新增字段直接并入唯一基线 `0001_init.sql`，不保留增量 `0002`。
- 不迁移、回填或保留现有开发数据；需要的开发样例只通过更新后的 seed 重新生成。
- CSV 只接受包含全部新字段的新版固定表头；旧模板直接报表头错误。
- 公开 DTO 或缓存 shape 变化不提供旧版本兼容；通过提升缓存 schema/namespace 使旧缓存自然失效。
- `submitter_contact`、`tag_suggestions`、`reject_reason`、原始访客键和审计日志继续保持非公开。
- 已发布和已下线活动仍可按现有规则访问；待审核和已驳回活动仍返回 404。

## Out Of Scope

- 本次不实现站内支付、预约或申请流程，只展示外部入口和说明。
- 本次不将票价拆分为数值、币种、票档或库存状态。
- 本次不改变热度去重、保留周期或首页 3/7/30 日热门排序规则。
- 本次不增加独立公告字段、公告历史或通知系统；异常说明复用活动描述。

## Acceptance Criteria

- [ ] AC1：不同的 `ticket_url` 与 `source_url` 同时显示；相同 URL 只显示一个购票入口。
- [ ] AC2：活动详情页显示格式化后的更新时间、用户状态和活动热度，且不泄露访客标识；下线、取消、延期依序覆盖日期推导状态。
- [ ] AC2a：近 30 日热度没有访客记录时明确显示 `0`。
- [ ] AC3：主办方、异常状态、入场方式、票价区间和开始购票/预约/申请时间可从公开投稿、管理员表单及批量 CSV 写入并在详情页读取。
- [ ] AC4：任一新增字段为 `NULL` 或空字符串时，对应内容完全不渲染。
- [ ] AC5：全新数据库只应用更新后的 `0001_init.sql` 即得到完整 schema；现有公开/下线/未公开访问规则保持不变。
- [ ] AC6：数据库、表单验证、DTO、页面辅助逻辑和相关回归测试覆盖新增字段以及 URL 相同/不同分支。
- [ ] AC7：CSV 模板和解析器只支持包含新增字段的新版固定表头，旧模板明确失败。
- [ ] AC8：存在主办方时详情页与 JSON-LD 使用该值；未填写时不产生空 organizer 数据。
- [ ] AC9：延期或取消的说明只来自活动描述，不新增或读取独立公告字段。
- [ ] AC10：仓库中只保留 `0001_init.sql` 一份迁移，不包含旧 schema、数据回填或双版本适配；本任务不自动删除或重建远程 D1。
