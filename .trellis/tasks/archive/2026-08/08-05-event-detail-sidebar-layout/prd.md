# 修复活动详情页侧栏错位

## Goal

活动详情页缺少“活动介绍”内容时，参加活动、主办方、入场方式、票价区间、开始购票/预约/申请等辅助信息仍保持在桌面端右侧栏，不因主要内容块缺失而自动移动到左侧。

## Background

- 已知异常示例：`https://acg.hobr.site/events/3`。
- 正常双栏参考：`https://acg.hobr.site/events/2`。
- 异常仅由可选的“活动介绍”栏缺失触发，活动详情数据本身不在本任务中调整。
- 已确认根因位于 `src/pages/events/[id].astro:253`：父容器仅在 `description && hasAsideContent` 时启用桌面两列网格，否则退化为纵向 flex；无介绍时的侧栏仅设置最大宽度，因而从左侧开始排列（`src/pages/events/[id].astro:276`）。

## Requirements

- 保持现有活动详情页的桌面端主内容/辅助信息双栏结构。
- “活动介绍”有无内容都不得改变辅助信息所属的网格列。
- 保持现有移动端单栏阅读顺序和内容展示能力。
- 修改范围限于活动详情页布局及必要的针对性验证，不改变活动字段、文案或数据来源。
- 当侧栏存在时，布局容器在桌面断点始终建立 `主内容 + 21rem 侧栏` 两列；无活动介绍时显式将侧栏放入第 2 列。

## Acceptance Criteria

- [x] 有“活动介绍”的活动详情页在桌面端继续显示为主内容在左、辅助信息在右。
- [x] 无“活动介绍”的活动详情页在桌面端仍将辅助信息固定在右栏，左栏可为空或由现有其他主内容占据。
- [x] 窄屏下页面保持单栏布局，辅助信息不溢出、不遮挡且内容顺序可读。
- [x] 针对详情页模板的回归测试明确断言“无介绍但有侧栏”使用桌面第 2 列，而不是仅依赖人工观察。
- [x] 项目现有的相关构建、类型或静态检查通过。

## Technical Notes

- 采用 Tailwind v4 响应式网格工具类完成修复，不新增组件、手写 CSS 或运行时逻辑。
- 保留介绍与侧栏同时存在时的边框、间距和 `21rem` 侧栏宽度。
- 现有 `test/event-detail.test.ts` 已对可选内容模板做源码回归断言，可在同一测试中补充布局约束。
- 线上浏览器检查在规划阶段因浏览器控制会话缺少安全配置而不可用，不作为已确认事实；实现仍需完成可用的本地静态、构建和页面检查。

## Out of Scope

- 调整活动数据模型或后台录入逻辑。
- 重写活动详情页的整体视觉设计。
- 修改线上示例活动的数据内容。
