# PRD - 首页双场景信息流设计

> Task: `08-05-homepage-dual-intent-feed` · Status: planning
> Owner: hobr · Created: 2026-08-05

## Goal

把首页重组为两个可直接扫描的用户场景：帮助购票用户发现近期未开票活动，帮助出行用户发现尚未结束的活动。两个场景都同时提供本地热门榜和全国热门榜，并沿用现有独立访客热度口径，减少用户在首页内反复筛选和跳转的成本。

## Background

- 当前首页依次展示本地精选 Hero、`3 / 7 / 30` 日热门榜和今日活动。
- 当前热门榜按近 `3 / 7 / 30` 日独立访客数排序，默认 7 日；同一 IP 的去重由既有访问记录机制负责。每个本地/全国榜最多展示 5 条。
- 当前地区切换会原子更新 Hero、热门、今日、URL、history 元数据和地区偏好。`HomepageContent.svelte` 是完整首页快照的唯一 hydrated owner。
- 活动数据已有 `admission_start_date` 和可空的 `admission_start_time`，但首页公开 DTO 与缓存合同尚未包含开票信息。
- 当前前端视觉合同是 Flowbite Svelte + Tailwind v4、Geist 字体、Flowbite 图标和现有语义 token。

## Requirements

### R1. 页面结构

- 保留现有大型本地精选 Hero，不压缩或移除现有首屏推荐体验。
- Hero 之后的现有热门榜与今日活动由新的双场景信息流取代，不在其后继续重复展示旧区块。
- 桌面端始终同时显示左右双栏：左栏为 `未开票`，右栏为 `未结束`。
- 移动端一次显示一个场景，使用顺序为 `未结束 / 未开票` 的分段控件切换，默认显示 `未结束`。
- 未启用 JavaScript 时，移动端必须回退为两个场景依次展示，不能使其中一类内容不可访问。

### R2. 未开票场景

- 只展示已发布、尚未结束、具有有效开票日期，且从当前中国本地日期起 14 天内开票的活动。
- 开票日期晚于今天时属于未开票；开票日期为今天且时间已知时，仅在该时间之前属于未开票。
- 开票日期为今天但未提供时间时，当天仍保留并显示 `今日开票 · 时间待定`；次日自动移出。
- 行内主信息突出开票日期/时间，次信息展示活动日期、地区与热度。
- 点击活动进入现有详情页，不在首页直接跳转外部购票地址。

### R3. 未结束场景

- 展示所有已发布且按现有中国本地日期/时间语义尚未结束的活动。
- 已经开始且尚未结束的活动显示 `进行中`；尚未开始的活动显示其开始日期/时间。
- 日期存在但时间缺失时沿用现有整日语义；同一活动在同一个小榜中只出现一次。

### R4. 本地与全国榜

- 每个场景内依次展示 `本地热门` 和 `全国热门` 两个独立小榜，不增加 `本地 / 全国` 切换控件，也不把两个范围混排。
- `本地热门` 使用当前导航地区的既有行政区前缀匹配；`全国热门` 不限制地区并继续显示活动所属地区。
- 全国范围语义保持完整，允许当前本地活动同时出现在本地榜和全国榜；不得把全国榜偷换成“外地榜”。
- 每个小榜最多展示 5 条，即每个场景最多展示 5 条本地活动和 5 条全国活动。
- 地区选择继续使用现有导航地区选择器及原子快照更新合同。

### R5. 热度与稳定排序

- 两个场景都以近 `3 / 7 / 30` 日独立访客数为第一排序信号，默认 7 日。
- 一个共享的 `3 / 7 / 30` 控件同时更新两个场景中的四个小榜，不允许产生不同热度窗口的混合快照。
- 没有访问记录的合格活动作为兜底保留：正热度活动始终排前，名额不足时再补入零热度活动。
- 热度相同或均为零时，`未开票` 优先更早开票；`未结束` 优先正在进行、再优先更早开始；其后按活动规模和 ID 保证稳定顺序。

### R6. 数据与交互一致性

- 首页首次请求由 SSR 输出完整有效快照；JavaScript 只做渐进增强。
- 地区或热度窗口切换时保留当前快照，直到 Hero 和四个小榜的新快照完整成功后一次提交。
- 快速切换时中止或忽略过期请求；失败不能清空当前有效内容。
- URL、普通链接回退、浏览器前进/后退、地区偏好和页面生命周期内缓存行为不得退化。
- 公开 DTO 只增加榜单展示需要的开票/活动日期与热度字段，不暴露外部来源、投稿联系、审核或完整数据库记录。

### R7. 视觉与响应式

- 沿用 Flowbite Svelte + Tailwind v4、现有语义 token、Geist 字体和 Flowbite 图标，不引入第二套组件库或动画库。
- 双场景区是无外层卡片的页面区段；桌面使用稳定 CSS Grid 和清晰中线，不制作四列窄卡片或嵌套卡片。
- 每个小榜使用紧凑行式布局，稳定对齐排名、标题、场景日期/状态、地区和热度；数字使用 tabular figures。
- 提供加载中、空结果、失败保留旧快照、键盘焦点和 reduced-motion 状态，不出现页面级横向滚动或布局跳动。

## Acceptance Criteria

- [ ] A1. 现有大型精选 Hero 保持可用，其后只出现新的双场景信息流，不再重复旧热门榜和今日活动区块。
- [ ] A2. 桌面左侧同时显示 `未开票`，右侧同时显示 `未结束`；移动端默认 `未结束` 并可通过 `未结束 / 未开票` 控件切换。
- [ ] A3. 无 JavaScript 时移动端仍可依次访问两个场景，且热度窗口与活动链接保留普通导航能力。
- [ ] A4. 每个场景同时显示最多 5 条本地活动和 5 条全国活动，全国榜允许包含本地活动。
- [ ] A5. `未开票` 仅包含今天至未来第 14 天内符合日期/时间规则的活动，并正确显示已知时间或 `时间待定`。
- [ ] A6. `未结束` 正确区分进行中与尚未开始，排除已结束、非 published 和重复活动。
- [ ] A7. 四个小榜按热度优先、零热度兜底和场景稳定次序排序；同 IP 热度去重机制不变。
- [ ] A8. 地区或热度窗口变化只提交完整新快照；过期请求、失败保留旧内容、URL、history 和地区偏好行为保持一致。
- [ ] A9. 严格公开 DTO 与缓存 guard 接受新合同并拒绝额外/非法字段，旧缓存 payload 自动 miss 后回源。
- [ ] A10. 查询边界、14 日/当日时间、零热度、本地/全国、投影、客户端解码和响应式源代码合同有回归测试。
- [ ] A11. `corepack pnpm test`、`corepack pnpm lint`、`corepack pnpm exec tsc --noEmit`、`corepack pnpm build` 和 `git diff --check` 通过。

## Out of Scope

- 不修改活动详情页、活动目录或管理后台的信息架构。
- 不改变热度采集、同 IP 去重、`event_visitors` schema 或清理机制。
- 不新增人工推荐、个性化推荐、登录态画像、直接购票、支付或库存能力。
- 不修改活动写入字段、数据库 schema 或现有管理员缓存失效映射。
- 不更换现有前端组件库、图标体系、字体或视觉 token。
